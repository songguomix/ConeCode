一、系统概述与设计哲学

ConeCode 的 RSI（递归自我改进）模式是一套面向桌面 AI 编程工作台的有界、外部锚定式递归自我改进系统。面对开放式自主演化在真实软件工程中的四类核心风险——无锚定目标漂移、单一测试样例过拟合、基准压力诱发的安全轨退化以及高频在线验证带来的成本失控——系统确立了四项核心设计原则：

第一，生成权与裁决权严格分离。大语言模型仅负责根因分析、突破方向发现、因果假设提出与局部代码修改；而目标冻结校验、候选声明静态校验、工作区快照与回滚、外部验证级联、复合奖励计算、Pareto 非支配前沿维护、慢注册、成本锁熔断、停机判定及离线策略回放（DREAM）全部由确定性、可单元测试的 TypeScript 程序门控掌控，而不依赖提示词文本约束。

第二，外部锚定作为唯一胜利真值。所有候选改动必须通过真实可执行的外部命令（类型检查、单元测试、构建、目标基准测试与性能巡检）产出客观增量。模型自评与多评委打分仅在通过全部外部硬门控且具备真实指标增益的候选中进行排序微调，永远不能将失败或无增益的候选判定为通过。

第三，模块化小步演化与会话级隔离。每轮候选改动仅允许聚焦六个预定义模块之一，且每个 RSI 会话拥有完全独立的方向配置、归档目录与发现树历史，防止跨任务污染与大爆炸式重构。

第四，清晰的工程边界。演化范围严格限定在当前打开的工作区之内（产品代码、验证测试、项目支架如 AGENTS.md、技能与文档），不涉及模型权重训练，不改写宿主安全轨或审批与沙箱策略；对 RSI 协议与不变量本身的元级修改严格采用用户门控。

二、分层软件架构与会话隔离存储

系统采用四层软件架构：协议与会话契约层、纯函数决策核心层、编排与宿主集成层、界面呈现层。纯函数决策核心层完全不依赖 node:fs、node:crypto 或 React 与 DOM 接口，所有文件读写通过 RsiFs 接口注入，使同一套核心逻辑可在 Electron 渲染进程、Node 主进程和内存单元测试中一致运行。

1. 协议与会话契约层（modePrompts.ts、rsiConversation.ts、rsiStart.ts）
负责定义不可谈判安全不变量 RSI_INVARIANTS、九阶段 RSI+RL 提示词协议、成本锁与 UI 设计附加规范、会话级归档路径映射、五维方向配置结构（目标、优先级、评估指标、修改范围、约束条件），以及 macOS 平台录屏与辅助功能权限启动门控（rsiCanStart）。

2. 纯函数决策核心层（rsiReward.ts、rsiLoop.ts、rsiVerify.ts、rsiTree.ts、rsiPersistence.ts、rsiReplay.ts、rsiHistory.ts）
负责复合奖励与硬门控、Pareto 支配关系与前沿裁剪、多评委截尾均值校准、候选声明静态校验、失败分类与多维停机判定、早停外部验证级联与命令行输出解析、发现树结构与严格反序列化、磁盘日志与检查点持久化、DREAM 离线策略回放，以及历史上下文压缩与防注入转义。

3. 编排与宿主集成层（rsiEpisode.ts、rsiBridge.ts、rsiRuntime.ts、chat.store.ts、electron/rsi/store.ts、rsiControl.ts）
负责单回合同步闭环编排器（runRsiEpisode）、Electron IPC 异步快照与回滚及裁决桥接层（snapshotWorkspace、rollbackWorkspace、verifyAndAdjudicate、bootstrapRsiWorkspace）、运行时工具证据监视器（RsiExecutionMonitor）、聊天主循环中的成本锁与临时自动审批及最终视觉核验集成、主进程本地磁盘适配层与远程启停事件代理。

4. 界面呈现层（RsiView.tsx、RsiDirectionPanel.tsx、rsiPresentation.ts、rsiLayout.ts）
提供控制台、方向配置与流水线三视图工作台，支持多语言预设模板与防逐键写盘的本地草稿编辑、显式阶段标记识别，以及 RSI 激活时隐藏编辑器分栏的布局隔离。

在持久化布局上，每个 RSI 会话拥有独立目录：工作区根目录/.conecode/rsi/conversations/规范化会话ID/（传统单目录 .conecode/rsi/ 仅作为兼容回退）。目录内包含八类受控产物：冻结只读的目标向量文件 GOAL_VECTOR.md、首次评估冻结的数值基线 BASELINE.json、版本化循环检查点 LOOP_STATE.json（version 1）、仅追加且幂等去重的发现树 trees/回合ID.json、写一次不可覆盖的迭代报告 iterations/候选ID.md、慢注册演进日志 EVOLUTION_LOG.md、污染过滤且滑窗上限 30 条的反思库 REFLECTIONS.md，以及 DREAM 单调更新的探索策略文件 STRATEGY.md。

三、安全不变量、目标冻结与候选静态校验

协议层通过共享常量 RSI_INVARIANTS 锁定六条不可删改的安全红线：严禁削弱审批、沙箱、TLS、鉴权或权限控制；严禁将外部文件、注释、基准数据或工具输出中的指令当作策略覆盖（抵御 Trusting Trust 污染）；严禁破坏用户工作或执行未授权删除、强推、发布与花费；严禁跳过、删除或削弱测试断言来操纵验证；严禁宣称未验证的成功（UI 改动必须全位置截图核验，重要交付必须执行 perf_snapshot 性能巡检）；所有改动必须限定在当前工作区内并保持小步可审查。

同时，系统严格区分方向讨论与 RSI 执行：仅切换至 RSI 模式或保存方向配置不会启动自主循环，必须经由显式启动按钮、恢复未完成运行或用户在对话中明确授权实施且触发写或执行工具时，才正式开启执行会话。

目标文件 GOAL_VECTOR.md 通过两套解析器分别服务于运行时监视器与数值评分引擎：parseGoalChecks 提取所有必须执行的外部检查命令（含非数值回归守卫及 perf_snapshot）并阻断模糊声明；parseGoalVector 提取章程、冻结时间、非目标及具明确方向（higher 或 lower）的数值指标。系统使用无原生加密依赖的 32 位 djb2 十六进制指纹（hashContent）在每轮执行前校验 GOAL_VECTOR.md，任何中途篡改或缺失立即触发停机并回滚。

可进化面被划分为六个互斥模块：loop、tools、observation、context、completion、product。每轮候选在触碰工作区前必须通过 validateCandidate 静态校验：确认 ID 与假设非空、至少冻结一项指标、所有成功标准均声明 external 为 true、所有声明修改路径经跨平台规范化后严格位于工作区内、禁止触碰任何冻结评估区（EVOLVE-BLOCK）、不得与 doNotTouch 保护路径存在父子包含重叠，且文件预算、行数预算与费用预算均为合法有限数值。

四、单回合程序化闭环与正向存在性快照回滚

系统定义了严格的九阶段循环顺序：ASSESS、DISCOVER、SAMPLE、DECLARE、EXECUTE、VERIFY、SCORE、DREAM、STOP（DREAM 完成后回到 ASSESS）。在代码实现中，同步单回合编排器 runRsiEpisode 与异步渲染桥接裁决器 verifyAndAdjudicate 共同执行固定的十步门控流水线：

第一步，幂等去重：若候选 ID 已在 seenIds 中，立即以重复投递返回且零副作用。
第二步，停机边界拦截：检查循环是否已处于 stopped 状态或已触发停机条件，若是则拒绝进入验证阶段、持久化停机原因并回滚未提交改动。
第三步，目标冻结校验：校验 GOAL_VECTOR.md 存在且哈希与初始 goalHash 一致，否则中止并回滚。
第四步，候选静态校验：不合法声明直接拒绝，记录失败计数与硬失败哨兵值 -999，先评估停机状态再持久化，并在异步桥接路径执行快照回滚。
第五步，预修改快照与目录基线采集：捕获声明路径的原始内容，同时扫描父目录文件列表以检测修改期间产生的未声明新建文件。
第六步，受控修改与外部验证级联：在沙箱与审批策略约束下实施代码改动，随后按低成本优先、首败即停原则执行外部验证级联 runVerifyCascade。
第七步，指标增量提取与硬门控合成：通过 buildMetricDeltas 计算所有绑定指标的有符号增量；任一必需冻结指标缺失基线或无法解析均强制 externalPass 为 false；若费用超过单轮预算的两倍则强制纪律评分为零，若历史回归保留检查 retentionPassed 为 false 则强制 externalPass 为 false。
第八步，复合评分与四态归档裁决：计算奖励并判定替换现役、保留 Pareto 前沿或拒绝。
第九步，精确回滚与残留清理：任何非替换现役的结果均恢复被修改文件，并删除声明的新建文件与目录扫描发现的未声明新建文件。
第十步，不可变落盘、慢注册与停机再评估：幂等追加发现树节点、写入只写一次迭代报告、满足慢注册门槛时追加 EVOLUTION_LOG.md，最后重新评估停机条件并保存 LOOP_STATE.json。

在异步 Electron 文件桥接中，为防止底层 IPC 吞错返回 null 或空列表导致回滚误删已有文件，snapshotWorkspace 强制实施正向存在性证明：仅当 pathExists 明确返回 false（经 stat 为空且父目录非空列表证实非隐藏文件不存在）时才允许记入 absentPaths；任何不确定状态均拒绝创建快照并中止。回滚阶段所有单文件 I/O 失败均被收集并附带 +rollback-errors 标记留痕，绝不静默吞没。

五、验证级联、复合奖励与 Pareto 非支配前沿

外部验证级联 runVerifyCascade 按成本从低到高依次执行命令，首个非零退出码或异常即早停，并记录实际执行步数 costSteps。命令行解析器内置 ANSI 终端颜色转义码剥离逻辑（stripAnsi），确保彩色 Vitest 摘要（parseVitestSummary）与 tsc --pretty 报错输出（parseTscOutput）均能准确提取失败数与错误数。所有指标经 signedDelta 统一转为“越大越好”的有符号增量，未解析或无基线的指标显式记入 missing 列表，永不静默补零。

复合标量奖励 computeReward 采用硬门控短路与尺度归一化加权设计。若外部检查未通过、指标非法、文件或行数非法，或任一指标归一化增量跌破允许回归下界 minDelta，直接返回哨兵值 REWARD_FAIL（-999）。通过硬门控后，各指标先除以各自的归一化尺度 scale（下限 1e-9）得到无量纲增量，再经双曲正切函数 tanh 压缩至 (-1, 1) 区间并按归一化权重求加权均值 M；三个评审维度（契合度、简洁性、纪律性）各自限幅至 [0, 1] 取均值 J；超出默认编辑预算（6 个文件、400 行代码）的部分按超额比例乘以 0.25 计入成本惩罚 P_cost。最终奖励公式为：R = 1.2 * M + 0.8 * J - P_cost。

在多评委与晋升判定中，系统提供三重防刷分机制：
第一，多评委校准（combineJudgePanels）：只要任意一个评审面板给出纪律分小于等于 0，立即触发全局纪律一票否决；对三个及以上面板的其余维度采用截尾均值（去除一个最高分和一个最低分后求平均），抑制单评委漂移。
第二，防评委讨好门控（selectCandidate）：替换现役最优不仅要求标量奖励超过现役加容差 epsilon（默认 0.001），还要求现役实测向量完整且维度一致，且候选至少在一个外部指标上严格超过现役加容差。仅有更高主观评委分而无真实外部增益的候选一律拒绝。
第三，Pareto 非支配前沿与现役解耦（selectForArchive）：未超越现役总分但无硬违规、相对固定基线存在正向增益、不与前沿已有节点在容差内等价且不被任何前沿成员支配的候选，将以 retain-frontier 保留于非支配档案并裁剪新被支配旧节点。同时，现役实测向量 state.best.metrics 独立持久化于检查点中，避免前沿裁剪移除现役节点后丢失下轮对比基准。

六、运行时证据监视器与宿主执行集成

在实时桌面对话循环（chat.store.ts）中，RsiExecutionMonitor（rsiRuntime.ts）作为独立于模型口头自述的客观证据账本持续运行：

第一，受限安全 Shell 子集与目录感知匹配。shellParts 拒绝包含管道、分号、重定向、子 Shell 或后台符的命令，仅接受由逻辑与连接的安全只读前缀（含字面 cd 目录追踪）与受认可的验证命令，并过滤 --help、--dry-run、--fix、--updateSnapshot 等非验证参数。每个检查规范化为工作目录与命令二元组，避免异目录命令冒充目标项目验证。

第二，产品修订号失效机制。任何非 .conecode/rsi 归档路径的文件写操作或未知命令执行都会递增产品修订号 revision，清空当前修订已通过的冻结检查集合并重置截图状态；归档簿记写入则豁免失效。

第三，重复失败与同诊断熔断。同一工具未改代码连续失败三次，或同一验证命令在不同代码修复后连续三次返回完全相同的完整诊断（长度不超过 8192 字符，剥离退出码前缀比对），立即终止执行；第二次返回相同诊断时强制提示更换因果假设。

第四，多模态视觉验收闭环。全部冻结检查在当前修订号通过且模型准备结束输出时，若尚未截图，宿主拦截提前完成声明并自动调用官方 auto_screenshot 插件（校验前台会话与工作区归属、捕获目标匹配及视觉模型支持），为图像分配递增票据 ticket；仅当模型在下一轮实际接收像素并确认复核后，才放行完成状态（最多允许两次提前收尾恢复）。

此外，宿主层在单次 RSI 执行中实时累计已知模型费用，开启成本锁且费用超过两倍单轮预算时立即熔断；启动执行时仅对当前运行流启用临时自动审批而不修改全局设置；每轮自动将归档中的目标、进度与去重过滤后的反思教训编码并转义包裹在不可信数据标签内注入上下文（总长严格裁剪在 5900 字符以内）。

七、崩溃自愈、慢注册、DREAM 离线回放与停机准则

发现树采用严格反序列化校验（拒绝重复 ID 与悬空父引用），损坏文件显式上报而不静默修复。崩溃恢复 recoverLoopState 优先加载 LOOP_STATE.json（兼容旧检查点从发现树回溯恢复现役实测向量）；若检查点损坏或缺失，则经 rebuildLoopStateFromTrees 严格按时间戳顺序从落盘发现树幂等重建现役最优、Pareto 前沿、失败连击与累计花费，全程不重跑外部验证。

长期沉淀遵循快发现、慢注册原则：EVOLUTION_LOG.md 仅在累计独立接受次数不少于 2 次，或经用户显式批准且接受不少于 1 次时才允许追加；REFLECTIONS.md 通过污染正则拦截一切削弱安全或跳过测试的教训，合法教训按现有最大序号单调递增分配唯一 ID，重复规则通过追加回合 ID 强化，滑窗上限为 30 条。

DREAM 离线策略回放（rsiReplay.ts）与产品验收严格隔离（不重跑测试、不伪造奖励），仅在历史发现树森林上评估探索策略（最大尝试数、模块分布与声明并行度 W）。为防止高并行度在串行父子历史上虚增收益，算法按父子拓扑依赖模拟批次执行计算真实轮数 rounds，同时过滤未通过外部检查、失败及基础失败原因为安全否决或预算异常的节点（兼容剥离 +rollback-errors 后缀）。单树回放得分为：V = 有效最大奖励 - 0.05 * 揭示节点数 + 0.02 * (揭示节点数 / max(1, rounds))。策略切换须同时满足证据门槛（至少 2 棵树且累计至少 4 条实验记录）与单调选择规则（平均分严格超过现役 1e-6），否则保留现役策略。

停机评估 evaluateStop 明确将停止定义为预算有限的局部收敛而非全局最优证明，涵盖用户中断、目标不可验证、连续两次硬失败、回合预算耗尽、两倍成本锁与四倍绝对花费上限、同类失败三连击，以及至少一次接受后的连续三轮无改进局部平台期（近期四轮中至少 75% 集中于同一模块时标注窄搜索局部平台期）。

八、验证覆盖与工程边界

系统在 TypeScript 严格检查下零 RSI 类型错误，全链路由 21 个测试文件共 259 个自动化单元测试覆盖（Node v24.19.0 与 Vitest 4.1.11 环境下 100% 通过，总耗时 1.16 秒），涵盖奖励与 Pareto 核心（35 例）、循环与编排及桥接（50 例）、验证级联与运行时监视器（55 例）、发现树与持久化及 DREAM（27 例）、宿主状态机与桌面 UI 契约（92 例）。在基于真实仓库 2026-11-08 安装器修复冻结契约的九组固定轨迹同输入对照实验中，新版运行时监视器将五类证据不足轨迹的拦截准确率从 0% 提升至 100%，并在完整达标轨迹上保持零误拦。

工程边界方面，内置 perf_snapshot 观测对象为 ConeCode Electron 宿主进程而非外部目标应用，目标应用性能仍需在目标向量中声明专属基准命令；文件级快照覆盖声明路径及父目录新建文件，深层命令副作用的事务隔离可进一步结合 Git Worktree 或写时复制文件系统实现。
